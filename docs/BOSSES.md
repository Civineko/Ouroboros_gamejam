# Boss 扩展协议

## 当前 Boss：噬环者

噬环者由净化积分触发，不依赖时间关卡。本局积分第一次达到 `15` 时出现，每局只出现一次；一次闭环跨过门槛也会正常召唤。

Boss 会在蛇头附近约 `180px`、手机与桌面镜头都可见的范围内登场，用 `1.6s` 将剩余普通敌人吸收到本体，随后按阶段召唤幼体。玩家不能通过碰撞直接伤害 Boss，必须闭环捕获围绕本体旋转的外置核心。

| 项目 | 规则 |
| --- | --- |
| 护甲 | 6 层 |
| 核心轨道 | 距 Boss 中心约 155px，便于单独闭环 |
| 普通闭环 | 破坏 1 层护甲 |
| 共鸣闭环 | 破坏 2 层护甲 |
| 核心恢复 | 命中后锁定 1.8 秒，但仍显示重组位置 |
| 击败奖励 | 净化积分增加 5，蛇身长度增加 120 |
| 击败演出 | 2.2 秒核心内爆、三重冲击波、彩色射线与净化粒子；HUD 同步显示战果 |
| 重复出现 | 同一局不会再次出现 |

## 三阶段

| 阶段 | 护甲范围 | 行为变化 |
| --- | --- | --- |
| 1 | 5–6 | 缓慢追猎，冲撞后不留危险尾迹，每次召唤 1 个幼体 |
| 2 | 3–4 | 移速和冲撞加快，冲撞路径留下临时危险尾迹，每次召唤 2 个幼体 |
| 3 | 1–2 | 追猎、冲撞和召唤频率进一步提高 |

冲撞前固定显示约 `1s` 的路线走廊和落点；召唤幼体前显示收缩波纹。凝滞减慢 Boss 移动、攻击、召唤和核心转动，但腐蚀尾迹仍按真实时间消退；护环可以抵挡 Boss 本体或尾迹的一次伤害。

冲撞预警期间必须同时出现四个独立信号：Boss 正式贴图染红、蓄力齿环在本体后旋转放大、场内红色路线走廊，以及不依赖相机位置的全屏红色脉冲与“立即离开红色路线”警报。进入冲刺瞬间再触发一次短红闪和轻微震屏；任一信号缺失时，其他信号仍足以让 Windows 与 Android 玩家判断危险。

入场和冲撞后的恢复阶段属于安全窗口，Boss 本体不会造成接触伤害。核心或 Boss 离开视口时，画面边缘显示方向指示；阶段切换分别使用珊瑚红、琥珀黄和紫色，并配合扩散波纹与 HUD 状态文案。

Boss 存活期间，护甲 HUD 必须持续显示明确的击败方法：“绕住外侧发光核心，让蛇首尾相接形成闭环”，不能只使用“破绽”“捕获”等需要玩家猜测的简称。外置核心暴露时额外显示脉冲捕获环和向内标记；冲撞、恢复与核心重组状态继续使用动态短提示。桌面端和移动端使用同一规则说明，不依赖 hover。

## 战斗音频

- `boss-spawned` 播放程序生成的出场音，并开始循环播放项目方提供的 `The_Hunter_s_Last_March.mp3`。
- Boss 从预警切换为冲刺时，引擎只发送一次 `boss-charge`；表现层播放项目方提供的 `大狗大狗叫叫叫-单句.mp3`，持续冲刺帧不会重复触发。
- `boss-hit` 播放核心破甲短音；`boss-defeated` 立即停止战斗 BGM 并播放 2.2 秒胜利短曲；`game-over`、结束本局和重开也会清理战斗音乐。
- 暂停、窗口失焦和 Android 切后台会暂停全部活动声音，继续游戏时恢复同一实例。运行时使用 HTML5 Audio 流式播放长 BGM，避免整首音乐在移动端解码常驻。
- 开发预览可能直接从蓄力状态开始、不会产生 `boss-spawned`；`startRound()` 会在用户手势内同步当前 Boss 状态并启动 BGM，正常 15 分流程仍由领域事件启动。HTML5 Audio 的 Android 解锁监听在 Scene 创建时提前安装，避免等到开始按钮的 `click` 阶段才注册而错过同一次 `touchend`。

Boss 最后一层护甲被破坏后，规则层保存击败位置并启动 `2.2s` 的只读表现状态。Phaser 在原位置绘制核心内爆、白色闪光、三重冲击波、16 道放射光和 30 个确定性彩色粒子；Vue 同步显示“净化完成”和 `+5` 战果。动画暂停时随游戏冻结，恢复后继续，不参与碰撞或积分判定。

## 模块边界

```text
engine/bosses/bossCatalog.ts       数值、阶段映射与节奏
engine/bosses/bossSystem.ts        可测试的状态推进、冲撞、核心和尾迹
engine/gameEngine.ts               积分触发、闭环伤害、幼体生成与领域事件
phaser/OuroborosSceneView.ts       只读取 Boss 状态并渲染
phaser/assets/placeholders/        正式资源前的程序占位轮廓
OuroborosView.vue                  只读护甲与阶段 HUD
```

Boss 状态必须保持可序列化，不能包含 Phaser、DOM 或 Vue 对象。新增 Boss 能力通过状态和领域事件进入表现层，不允许在 Boss 规则中直接操作相机、布局或平台 API。

## Windows 与 Android 输入路径

- Windows：鼠标点击/拖动或方向键/WASD 转向，现有暂停键继续有效。
- Android：单指按下和拖动完成转向；Boss 战不要求 hover、多指、右键或实体键盘。
- 冲撞预警至少保留 `0.8s`，核心视觉和判定半径不能要求像素级触控精度。
- 危险尾迹控制数量和透明叠加，不能为每一帧创建长期存在的 Phaser 对象。

## 新增 Boss

1. 在 `engine/types.ts` 约定可序列化状态和领域事件。
2. 在独立 catalog 和 system 中实现阶段与能力，并添加相邻测试。
3. 在 `gameEngine.ts` 只负责触发、通用伤害和现有系统协调。
4. 在 `ART_ASSETS.md` 和资源 catalog 登记正式资源，未交付时使用程序占位。
5. 明确键鼠和纯触摸两条完整路径，验证暂停、后台、恢复和重新开始。
6. 运行类型检查、测试、浏览器桌面/移动尺寸检查，并在打包链可用后验证 `.exe` 与 `.apk`。
